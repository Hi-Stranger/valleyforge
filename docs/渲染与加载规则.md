# 渲染与加载规则

生效日期：2026-11-01。适用于城镇、原野、矿洞、战斗场景及后续地图的渲染、素材制作与加载。本文规定统一实施方向，具体缓存规模与资源预算按目标设备和场景实测确定。

遵守 [项目协作规则](../AGENTS.md) 的预览与确认流程及 [编码规则](编码规则.md)。本文规定实施要求，不自动授权迁移现有地图或改变已确认画面、动作与玩法。

## 操作前必读

检查、排查、设计、预览、实现或修改渲染、镜头、环境动画、缓存、图集、资源加载或切图前，必须先读取 [项目协作规则](../AGENTS.md)、[操作与验证规则](操作与验证规则.md) 和本文；相关方案与预览阶段同样适用。涉及代码、脚本或配置修改同时读编码规则，涉及绘图与素材整理同时读 [绘图与素材规则](绘图与素材规则.md)。

涉及地图、Boss、怪物展示或独立异常状态特效时，按协作入口同时读取相应专项规则。性能优化也不能覆盖专项的固定帧规格、锚点、已确认画面与动作要求；需要改变表现的部分先另行预览确认。

## 1. 统一绘制流程

- 沿用 Canvas 2D 和 `requestAnimationFrame` 主循环，使用时间差驱动角色、镜头与动画，避免动作速度随设备刷新率变化。
- 绘制顺序统一为：静态地面缓存 → 地面特效 → 按脚部锚点深度排序的景物、角色和怪物 → 前景特效 → UI。桥、水、树冠等按实际遮挡关系分层，不能将所有特效强行叠在最上层。
- 镜头、角色和场景使用一致的世界坐标与变换。像素素材默认关闭平滑；允许柔和光晕使用适当采样，但须恢复绘制状态，避免影响其他图层。
- 镜头平移不得触发素材重载、地面重复拼装或 Canvas 尺寸反复重设。窗口尺寸或缩放实际变化时才调整对应画布；检查手机分数缩放下的接缝、抖动与透明边缘。

## 2. 地面缓存按规模选择

- 保留可编辑瓦片、地形分层、景物和碰撞数据。运行时合成地面缓存属于绘制优化，不能用概念整图代替模块化地图。
- 当前规模的小地图，在目标设备尺寸与内存预算允许时，优先一次合成静态地面；镜头移动仅裁切绘制已有缓存。1536×1024 的单层 RGBA 缓存理论像素占用约 6 MiB，并非未来地图的固定尺寸或内存上限。
- 大地图或整图缓存超出预算时，采用世界坐标固定的分块缓存；加载可见块与有限邻接块，限制总驻留量并淘汰远处未使用块。镜头移动不得重拼已经有效的块，也不得反复重建整个可见区域。
- 静态缓存仅在相关地形、图集、尺寸、图层或地形版本改变时失效；分块地图只重建受影响块。动态物件、光照、角色与战斗特效单独绘制。
- 缓存生成较重时分批完成；进入场景前准备首屏必需缓存，后台准备不得造成持续长帧。分块边缘按实际采样方式检查，避免接缝与光照断层。

## 3. 动画、光照与视野裁剪

- 稳定光晕、重复渐变及可复用特效预先生成小型纹理或缓存，运行时复用。避免每帧重复创建大量渐变、临时画布、图像读回或大型临时对象。
- 环境动画可按表现需要采用 20–30 Hz 的效果缓存，主画面仍随 `requestAnimationFrame` 绘制。不得将环境缓存频率当作整个游戏帧率上限，也不得据此降低角色移动、输入或战斗判定频率。
- 动画采用游戏时钟并遵守已有暂停语义。视野外可跳过效果采样与绘制，重新进入时按游戏时钟恢复正确阶段；影响玩法的怪物与战斗逻辑不能仅因不可见而随意停算。
- 裁剪按完整可见边界，包含树冠、光晕、烟雾、武器与跳跃偏移，必要时留边。禁止只用脚点判断可见性造成边缘突然消失。
- 优化须保留已确认的特效强度、颜色、遮挡、动作节奏和角色比例；需要改变这些表现时重新预览确认。

## 4. 素材与内存

- 按实际游玩显示尺寸及必要放大余量制作素材，避免把过大源图直接用于小角色或小景物。裁掉无效透明区域，保留采样边距，同步检查帧坐标、锚点及碰撞数据。
- 按场景与用途拆分图集，公共角色、UI 和通用素材共享。不得为减少请求数将所有地图、Boss 与技能塞进常驻大图集；图集尺寸须在目标手机上验证。
- 分别核算解码图像、地面 Canvas、特效缓存及同时驻留的共享资源。RGBA 像素占用以 `宽 × 高 × 4` 字节估算，浏览器实际内存可能更高；PNG 文件大小不能代表运行内存。
- 缓存必须有明确所有者、失效条件、驻留范围和释放时机。不得只缓存不回收，或用大量预渲染帧换取无法控制的内存增长。

## 5. 分阶段加载

- 维护公共资源和各场景的必需、可选资源清单。优先准备公共资源与当前场景必需内容，当前场景不得等待无关地图、Boss 或战斗场景素材。
- 网络加载、图像解码及首屏必需缓存完成后再允许进入场景，避免角色已可移动但地面、碰撞或关键景物尚未就绪。
- 展示真实加载阶段或已完成项进度，不将请求完成冒充全部准备完成。必需资源失败时明确提示并支持重试；可选资源失败不阻断已具备完整基本表现的场景。
- 临时演示确需其他场景素材时，将其列为该功能的依赖并在需要时加载，不能因演示功能使无关素材成为所有场景的首屏依赖。

## 6. 切图与资源生命周期

- 使用统一资源管理入口，以资源地址与版本标识去重，同一资源的并发请求共享加载结果；失败请求不得永久占据成功缓存。
- 沿用项目版本缓存约定，更新的资源与入口版本一致；不得每帧或每次取资源时追加随机参数破坏缓存。请求与解码采用受控并发，具体数量按设备与资源规模验证。
- 当前场景可交互后，在空闲且预算允许时按需预取可能进入的相邻场景；预取不得与首屏或正在进入的场景争抢关键资源，也不得预取全部地图。
- 切图时取消可取消的旧任务；不可取消的加载或解码通过场景标识忽略过期结果，避免旧任务覆盖新场景。重试和重复切图不能造成重复注册或重复持有。
- 释放无人使用的场景图像引用、Canvas、特效缓存与相关监听；具备显式关闭接口的位图及时关闭。共享资源仅在没有使用者时释放；保留缓存必须有容量与淘汰策略。
- 页面整页跳转与同页切图按各自生命周期处理，不将浏览器 HTTP 缓存误认为应用已实现共享资源管理与内存回收。

## 7. 验证与交付

- 至少分别检查冷启动首进、缓存后再次进入、角色独立移动、镜头连续跟随、战斗高负载及多次地图往返；记录设备、浏览器、分辨率、缩放与测试路径，保证前后对照条件一致。
- 记录加载阶段耗时、请求量、资源解码与缓存构建成本、帧耗时分布和明显卡顿；查看往返后的资源驻留是否持续增长。工具无法直接读取真实内存时标明估算，不能当作实测值。
- 性能目标按目标设备记录；60 Hz 设备可参考约 16.7 ms 的单帧总预算，但不能以平均帧率代替长帧与操作响应检查。桌面模拟器或桌面浏览器数据不得冒充手机实测。
- 用同画幅、同镜头与同缩放对照优化前后画面；检查像素边缘、透明度、光晕、遮挡和动画节奏。功能检查或绘制调用减少不等于真实手机流畅度已通过。
- 报告实际执行的验证及限制。仅写规则不宣称运行性能已改善；代码迁移仍须单独预览、确认、提升游戏版本并完成相关验证。

## 8. 当前实现与待迁移项

以下为工作区 `v2026.11.01.9` 的情况，后续实施时须重新核对代码，不将本节当作永久不变的状态。

| 项目 | 当前情况 | 后续要求 |
| --- | --- | --- |
| 主绘制 | Canvas 2D 与 `requestAnimationFrame`，共用场景排序流程 | 沿用统一绘制与时钟原则 |
| 城镇与原野地面 | 共用静态缓存，在加载阶段分批合成，镜头裁切复用 | 保持失效与释放约定；当前每张地面约 6 MiB |
| 矿洞地面 | 世界坐标固定分块、有限邻块与 LRU；复用视口画布保持采样，合计采用 32 MiB 目标预算 | 按设备与视口核对可见集合的最低内存，诊断报告超预算；其他未迁移地图另行规划 |
| 城镇动态效果 | 光晕小缓存复用，环境特效按 20 Hz 采样 | 保持表现，统一生命周期与裁剪约定 |
| 原野水纹与游鱼 | 共用水域准备与像素读取，按 30 Hz 缓存动画；初始化后释放源图与临时画布 | 保持水面遮罩、暂停及遮挡表现 |
| 城镇、原野与矿洞加载 | 共用资源入口，URL 与版本去重、最多 4 项并发、等待解码；首屏不等待演武与战斗背景 | 野猪王动作只属原野必需资源；矿洞战斗裁图按需准备，随后释放全尺寸输入图 |
| 进度、预取及回收 | 显示准备阶段；场景就绪后在前台、关键队列空闲、实际 idle 且像素预算允许时预取，使用前等待；卸载回收 | 预取默认预算 64 MiB、预留 4 MiB；无 idle API 时仅按需加载，不预取相邻整张地图；BFCache 由浏览器管理 |
