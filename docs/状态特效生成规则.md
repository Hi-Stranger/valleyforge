# 独立状态特效生成规则与提示词

适用于《溪谷铸途 Valleyforge》人物与普通怪物的独立异常状态素材。后续生成这类素材前先阅读本文；用户最新明确要求优先。

本文记录素材制作方案，不代表状态系统已经实现，也不直接确定伤害、持续时间、抗性和控制规则。

## 1. 当前项目依据

- 游戏为手机横屏优先的 2D 像素 RPG，采用俯视略带正面的视角。
- 参考现有 `game/assets/sprites.png` 和溪畔原野实机画面，保持小尺寸角色的像素密度。
- 当前基础人物向下待机帧的裁剪尺寸约为 13×20 像素；运行时还有角色与相机缩放，不能把它当作最终屏幕尺寸。
- 当前绘制关闭图片平滑；素材应采用清楚的像素簇、简洁轮廓和有限色阶。
- 现有剑气以青蓝、浅白为主，异常状态通过形状及配色区分。
- 人物、史莱姆、野猪等体型不同；探索与战斗的显示比例也不同。尺寸和锚点应在接入时按实际绘制范围适配。

## 2. 制作与使用规则

1. 状态特效与角色动画分离，不为每个角色预先合成全部状态组合。
2. 每次生成一种特效，使用“通用提示词＋对应专项提示词”；同系列素材保持像素密度与配色一致。
3. 参考图优先采用当前人物、怪物或实机截图。角色只作为参考，不得出现在最终独立特效图集中。
4. 默认图集为 8 列×1 行、每帧 64×64、总尺寸 512×64 像素；眩晕使用每帧 32×32、总尺寸 256×32。以上是本方案的新规格，不是项目已经支持的加载格式。
5. 持续状态无缝循环；命中与解除效果一次性播放，最后一帧完全透明。
6. 身体类默认脚底锚点为帧内（32，52）；眩晕使用头顶中心锚点（16，16）；雷电命中使用命中中心（32，32）。坐标均相对于单帧左上角。
7. 不逐帧自动裁边，不改变格子大小；保留透明边距，防止切帧抖动和相邻帧污染。
8. 身体覆盖效果保留透明空隙，不遮住角色动作、敌人预警与生命信息。不要在素材里加入名字、数字、血条、状态文字或黑色底框。
9. 角色染蓝、受击闪白等可由渲染控制，不必重新生成人物图片。特效播放速度由运行时控制，图集帧数不等于游戏帧率。
10. 生成工具的尺寸、透明通道及帧数不能仅靠提示词保证。正式使用前必须核验并整理，不能直接把生成结果视作已验收的正式资源。
11. 状态逻辑与视觉分离：雷电伤害不自动等同于麻痹，冰属性伤害不自动等同于冰冻。具体触发、持续时间与叠加方式以实现任务为准。
12. 如涉及 Boss 的设计、素材或实机表现，先阅读 [Boss 规则](Boss规则.md)，遵守项目的先预览、确认后实施要求。本文不授权修改 Boss，也不确定其状态抗性。

## 4. 通用提示词

将本段与下方一种专项提示词一起使用。

```text
为现有游戏《溪谷铸途 Valleyforge》制作独立异常状态特效序列帧。

【项目风格】
手机横屏优先的 2D 像素 RPG，场景包括溪畔草地、树林、山地和昏暗矿洞。
采用俯视略带正面的游戏视角，单位能向上下左右移动。
人物基础图像约 13×20 像素，运行时放大绘制。
特效必须与这种小尺寸像素角色协调，并以提供的当前项目参考图为准。

采用清楚的像素块、简洁轮廓，每种特效约 4—6 种主要颜色。
强调小尺寸辨识度，减少碎屑和细线。
不采用写实光效、平滑渐变、大面积模糊或复杂魔法阵。
现有剑气是青蓝色与浅白色；状态特效通过形状和配色保持区别。

【素材用途】
只生成独立特效，不绘制人物、怪物、武器、场景和 UI。
供人物与普通怪物共用，不绑定特定身体轮廓。
适合叠加在双足人物、矮小史莱姆和横向野猪身上。
中央保留透明空间，保证角色动作可见。
不绘制名字、状态文字、血条、数字、底框、水印或签名。

【默认图集规格】
透明背景 PNG，8 列×1 行，共 8 帧。
每帧 64×64 像素，整张图集 512×64 像素。
若专项提示词另有尺寸要求，则采用专项要求。
各帧等大并严格对齐，固定视角、像素密度、锚点和总体范围。
禁止自动裁切每帧，禁止无意的位置漂移。
边缘保留至少 4 像素透明安全区。
不绘制网格、分隔线、帧编号和文字。
背景必须真正透明，不能画棋盘格背景。

【默认定位】
身体类每帧以坐标（32，52）为单位脚底锚点，效果从这里向上展开。
左右均衡，不依赖单位朝向。头顶类另用中心锚点。

【动画】
持续状态制作无缝循环，命中和解除效果制作一次性动画。
帧间动作清楚，避免只改变整张图透明度。
不绘制整屏闪光或干扰观察的高频爆闪。
```

## 5. 专项提示词

### 5.1 眩晕：status-stun.png

```text
制作《溪谷铸途》的眩晕头顶特效。
覆盖默认尺寸：每帧 32×32，8 列×1 行，整张 256×32 像素。
固定锚点为每帧中心（16，16）。

三个简洁的金黄色小星星沿扁平椭圆轨道旋转。
轨道总宽约 24 像素、高约 10 像素。
星星使用暖金、浅黄和少量棕橙阴影，每颗约 3—5 像素大小。
不绘制实体轨道线，不添加大片光晕。
8 帧完成一圈旋转，前侧略亮、后侧略暗，表现前后空间感。
不产生整体上下漂移，无缝循环。
只绘制星星和极少量闪点，不绘制角色、头部或 UI。
该素材由游戏放到单位头顶，不使用脚底锚点。
```

### 5.2 冰冻外壳：status-freeze-shell.png

```text
制作《溪谷铸途》的冰冻外壳循环特效。
默认 64×64 帧尺寸，脚底锚点（32，52）。
冰壳范围约为 x=12—51、y=8—53。

略不规则的多面冰晶外壳，底部较宽、顶部略收窄。
中等明度冰蓝外轮廓，浅蓝棱线与少量冷白高光。
用少量大块折面表现厚度，不堆积细碎纹理。
中央大部分透明，仅保留稀疏裂纹与轻薄冰面，能清楚看到后方角色。
不按人形塑造，不出现头、手臂或腿的轮廓，也能容纳矮胖怪物。
不绘制地面冰圈或大范围霜雾。

8 帧保持外轮廓稳定，仅让少数棱面高光依次闪烁。
不整体缩放、抖动或上下移动，无缝循环。
表现安静、牢固、无法行动的冰冻感。
```

### 5.3 冰冻解除：status-freeze-break.png

```text
制作与 status-freeze-shell 配套的冰壳碎裂动画。
默认 64×64 帧尺寸，脚底锚点（32，52）。
以已选定的冰壳图集为参考，保持相同轮廓、尺寸、像素密度和配色。

8 帧一次性播放：
第 1 帧：完整冰壳出现两三条明显裂缝。
第 2 帧：裂缝扩展，冰壳开始分离。
第 3 帧：冰壳破开，形成数块较大冰片。
第 4—5 帧：冰片向左右散开，略向下掉落。
第 6 帧：只剩少量小冰晶。
第 7 帧：残留两三个微小冰点。
第 8 帧：完全透明。

碎片数量适中、方向清楚，不用大片白光。
碎片不得超出单帧边界，不绘制角色或地面。
```

### 5.4 雷电麻痹：status-shock.png

```text
制作《溪谷铸途》的持续雷电麻痹特效。
默认 64×64 帧尺寸，脚底锚点（32，52）。
电弧范围约为 x=12—51、y=10—51。

每帧出现 2—4 段短小折线电弧，沿身体两侧与上方交替跳动。
淡紫白核心、紫蓝主体、较暗紫色边缘，区别于项目青蓝剑气。
明确的像素折线，主体厚约 1—2 像素。
局部允许少量 2×2 像素电火花。
中央大部分透明，不形成实体护盾，不描摹人形。

8 帧交替表现左侧放电、右侧放电、上下短接及短暂减弱。
形成不规则但可无缝循环的通电感。
不画天空落雷、环绕法阵、人物或人形电流轮廓。
```

```text
制作《溪谷铸途》的雷电命中瞬间特效。

不包含武器、角色、地面或天空。
```

## 6. 正式使用前的检查

- 核对图集尺寸、列数、帧数和真正的 Alpha 透明通道，排除棋盘格、文字与水印。
- 切帧后逐帧检查锚点、边距与像素密度；循环接缝自然，单次动画结束无残影。
- 用当前人物、史莱姆与野猪检查覆盖范围，分别查看探索及战斗比例，避免所有单位采用同一个固定尺寸。
- 在明亮草地、树林和昏暗矿洞背景上检查辨识度，并按手机实际显示大小查看。
- 检查与剑气、伤害数字、生命条和攻击预警同时出现时的可读性。
- 多状态同时显示时控制覆盖密度；显示优先级与组合表现由后续实现任务确定。
- 正式加载图集需要单独实施。按 [编码规则](编码规则.md) 更新版本并运行相关检查；仅维护本文不强制提升游戏版本。
