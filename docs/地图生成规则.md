# 地图生成规则：以当前溪畔原野为基准

版本：2026-10-29。用途：后续地图设计、AI 素材生成、Tiled 制作和游戏接入时共用的项目规范。用户最新要求优先于本文；本文本身不授权修改游戏、覆盖素材或重新构建地图。

## 1. 参考基准与使用方法

先阅读本文，再查看以下项目内参考，不能只根据文字重新猜测风格：

- 当前环境外观：[meadow-environment.png](../previews/meadow-environment.png)。这是草地、道路、河岸、树木和景物密度的主要基准。
- 当前游戏效果：[meadow-ingame.png](../previews/meadow-ingame.png)、[meadow-mobile.png](../previews/meadow-mobile.png)。核对人物、怪物、镜头和横屏体验。
- 最初布局参考：[reference.png](../source-assets/meadow/reference.png)。用作构图来源；后续已确认的当前效果优先。
- 当前水面效果：[水面替代方案预览](../previews/stream-alternatives.html?fish=1&still=1&gentle=1&wave=2.3)。查看时保留链接参数。
- 实现说明：[溪畔原野.md](溪畔原野.md)。素材来源、生成命令和现有功能以此文及实际代码核对。

为新地图先列明：主题、尺寸、主地形、入口与出口、路线、普通怪物、Boss 地点、需要复用的素材、需要新增的素材。必须先生成预览图供用户查看，等待用户明确确认当前方案后，才能制作可玩地图；即使用户直接要求修改代码或直接实现，也不能跳过预览与确认。现有地图的任何修改同样遵守此流程。

## 2. 地图类型与空间尺度

- 采用连续、可自由行走的野外遇怪地图。参考经典《世界OL》H5、《梦幻西游》手游野外地图的旅行和遇怪感觉，视觉保持本项目像素风。
- 保持当前“大地图探索与接触怪物 → 独立即时战斗 → 返回遇敌地点”的结构；不要自行改为回合制、暗雷遇敌或大地图直接战斗。
- 草地和道路两侧应有可行走空间。道路负责指引，不应成为唯一可走的狭窄走廊。
- 不采用四象限刷怪场、圆形竞技场串联、房间迷宫、对称关卡或大片相同空地。
- 当前原野为 1536×1024、32 像素地形网格。这是现有实现参数，不是未来所有地图的固定尺寸。
- 后续大区域可先以当前原野宽高各约两倍作为规划起点，再按主题和运行成本调整；这是建议规模，不代表现有地图已扩建。扩大世界范围时保持人物、怪物、景物和实际游玩镜头比例。
- 区域总览可以拉远视角，但还应提供一张正常游玩视角预览，避免只靠缩小角色制造“大地图”的感觉。

## 3. 画风与环境密度

- 固定斜俯视二维像素视角；与当前原野的树木、棚屋和木桥透视一致。避免等距菱形地图、地平线、写实三维渲染或油画笔触。
- 草地采用偏橄榄绿、黄绿色的低对比块面变化；土路为暖黄褐色；水体为清晰蓝青色。不同主题可换色，但要保持像素尺度、明暗关系和饱和度协调。
- 地表低噪声、可重复使用，不铺满高对比碎点，不出现明显棋盘格、接缝和规则条纹。
- 道路有宽窄和自然弯曲，草土交界带少量碎草、石粒及不规则边缘；避免平滑矢量色带和机械直角。
- 维持疏密对比：树丛集中在边缘、前景和局部小组团，中央留出连续开阔地。花草、灌木多靠近树根、石头及河岸，避免均匀撒满画面。
- 棚屋、桥、路标、岩石等只作适量地标。野外刷怪地图不能变成居民区、集市或农场。
- 生成新环境时保留当前人物、头像、怪物素材和比例，除非用户另行要求更换。概念图里的新角色不自动成为游戏资产。

## 4. 地形、道路与连通性

- 顺序：区域地形轮廓 → 河流或山系 → 通行路线 → 地标及 Boss 地点 → 植被景物 → 遇敌点 → 细节。
- 河道应有连贯走向、可读岸线、浅水及岩土断面；水面、岸石、芦苇与陆地自然衔接。
- 跨河通过桥梁；桥的两端均连接可走地面。树、石块、栏杆不能挡住桥头或洞口。
- 山崖的高差连续，跨层使用真实连接的坡道或台阶。视觉上可走的位置应与碰撞一致。
- 大区域建议具备一条贯穿主路、至少两条可绕行并重新汇合的路线，以及少量有目的地的支路；数量按区域规模调整，不为满足数量制造重复路口。
- 地标之间有行走距离和景观变化。入口、出口、桥梁、普通怪物、采集点及 Boss 地点均可到达，出生点避免直接触发战斗。

## 5. 普通怪物与 Boss

- 普通怪物以单只或松散小群自然分布在可走草地、路边、林间、山脚。保持足够间距，让玩家能选择目标和绕行。
- 不把怪物整齐排队、不把一类怪统一圈进圆形场地，不把地面怪物放在水上、实心景物中、陡壁上或无法到达的位置。
- 刷怪密度按实际镜头和移动速度检查，不能只凭总览上的怪物数量决定；扩大区域时同步增加有效分布范围，避免只有道路尽头有怪。
- 后续新野外区域默认规划至少一个明确的 Boss 洞穴或固定刷新地标；也可按用户指定改成遗迹、巢穴或矿洞。
- Boss 地点嵌入自然地形，通过支路接主路线；洞口前留出可到达的空间，普通刷怪路线不必强制穿过 Boss。
- 用洞口造型、足迹、骸骨、矿轨或少量特殊光源识别首领地点。预览可加小型名称标记，不用大红圈、虚线边界、路线箭头覆盖成图。
- Boss 外观应与周边普通怪物有区别，比例保持可信；刷新时长、脱战条件和奖励属于玩法参数，需单独指定，不能把概念图当成已实现配置。
- 当前溪畔原野未加入 Boss 洞穴。以上是新地图规划规则，不描述当前原野已实现功能，也不要求自动给现有原野加洞。

## 6. 水面与环境动画

- 原野同类溪流沿用当前轻微起伏、明暗变化和细波反光，不把整张水面向下游滚动。
- 小鱼只在水面范围活动，避开桥、礁石、岸边植物及陆地；鱼的尺寸、数量和颜色从当前原野效果出发，再按新河道面积调整，不机械复制固定数量。
- 水纹和鱼的绘制顺序不能覆盖桥面、树木和实心岸景；不参与碰撞、遇敌和战利品。
- 沿用游戏时钟、暂停冻结、视野外跳过更新和缓存的现有方式。普通静态截图不能作为动画效果已验收的证据。

## 7. 从预览到可玩地图

- 概念整图仅用于设计参考，不作为游戏唯一整幅背景，也不要把整图机械切成碎块冒充模块化地图。
- 制作可复用地表材质、边缘变体和独立景物；树木、棚屋、桥、洞口等需要真实透明通道，不保留白底、棋盘底或背景残边。
- 风格参考、环境地表、独立景物、河流、角色和怪物分开生成及管理。保留原始素材和版本，默认不覆盖旧版。
- 图块地图保留地形、景物、碰撞、怪物及入口出口等可编辑数据。碰撞按物件脚部实体处理，树冠允许遮挡；深度排序与现有角色逻辑一致。
- 具体网格尺寸、图集结构、素材目录、Tiled 与导出脚本的主从关系应在新区域说明中明确，不把原野当前 32 像素网格强加到所有区域。
- 不因制作新地图擅自改变人物模型、攻击与技能、奖励结算、背包、装备、存档或其他已有区域。
- 重新构建可能覆盖生成文件；执行前检查该地图的构建说明和已有手工编辑，不把地图生成命令当成只读预览。

## 8. 可复用提示词

### 环境与遇怪地图概念图

将方括号内容替换为新区域要求，并附上当前环境及游戏截图作参考。

```text
为《溪谷铸途 Valleyforge》设计一张[区域名称/主题]野外遇怪地图预览。
风格参考：项目当前 previews/meadow-environment.png；人物与镜头比例参考 meadow-ingame.png 和 meadow-mobile.png。
保留当前原野的固定斜俯视像素风、低对比地表、自然草土边缘、独立树木景物与清晰岸线。
地图规模为[世界尺寸或相对当前原野的倍数]，实际游玩时保持当前角色与镜头比例；提供区域总览及正常游玩视角。
这是一片连续可走的野外，地形为[地形]；入口位于[位置]，出口为[位置]。
主路贯穿区域，支路可绕行后汇合，地标之间有足够行走距离；道路两侧也能探索。
树群、山石、花草疏密有别，保留大片互通的可走地面；建筑只保留少量必要地标。
[普通怪物]以单只或松散小群散布在可到达的陆地，大小与当前人物和怪物一致。
在[位置]设置[Boss洞穴/巢穴/遗迹刷新点]，支路接入，入口可辨认，洞前有可达空地。
大地图用于探索遇怪，接触怪物后进入独立战斗；不将地图设计成多个竞技场。
不出现刷怪圈、四象限分区、整齐排队的怪群、路线箭头、密集标签、巨大Boss、UI或水印。
不更换现有角色模型，不将本次概念图视为已实现功能。本次仅生成预览。
```

### 地表与独立景物素材

```text
参考已确认的新区域预览及当前溪畔原野素材，生成[地表材质/独立景物]。
保持统一像素尺度、斜俯视透视、调色和光照；严格按[图集规格、尺寸及素材清单]输出。
地表可重复使用，块面低噪声、边界无缝，不含树木、人物和怪物的烘焙影像。
独立景物完整、不互相遮挡，保留真实透明背景，底部锚点和脚部碰撞范围清晰。
不得输出完整场景截图代替独立模块；不得擅自重做人物、头像、怪物或技能。
```

## 9. 交付检查

- 预览能看清整个区域范围，也能在正常镜头下看清角色、怪物与地形。
- 道路及地标自然，怪物散布有节奏；无四象限竞技场和人为圈区。
- 所有入口、出口、怪物、桥头、洞口与 Boss 点可达，水域与实心景物阻挡正确。
- 地表无明显接缝，透明景物无底色残留，遮挡和深度正确，跨区无断层。
- 有水纹或鱼时检查实际动画、遮罩、暂停和视野外更新，而非只检查静态图。
- 制作可玩版本时再运行该区域适用的素材检查、连通检查、遇敌与返回、区域往返和手机横屏检查；仅写规则或生成概念预览不宣称这些检查已通过。
- 保存预览、参考素材和区域说明，清楚区分“设计要求”“概念预览”“已经实现”。
