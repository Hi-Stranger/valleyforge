## 矿洞地面缓存

`chunk-terrain.mjs` 以世界坐标固定的 512px 分块复用四层瓦片，边缘带一格采样余量。加载阶段分批准备首屏，并优先准备预算能容纳的邻近块。镜头移动复用已有分块；遇到未准备区域时只补对应块，远处缓存按 LRU 淘汰。地形版本、图集、尺寸或图层改变时失效，离开场景时释放，未完成的准备任务会取消。

为保持小数缩放时的采样，先将可见分块按原像素组合到视口画布，再像原实现一样统一缩放。视口瓦片范围未变时直接复用画布；复用有限的视口尺寸，避免随镜头反复重设尺寸。窗口尺寸变化时才清理这一组视口缓存。

地面分块与视口画布合计采用 **32 MiB 目标预算**，准备邻块前先预留视口画布空间。当前验证的手机横屏视口内保持在预算以内。极端大视口若其可见集合本身超过配置预算，优先保留当前可见内容，并通过 `overBudget` 明确报告；不能据默认数值宣称任意屏幕都满足同一内存上限。设备适配时须核对预算，不能通过反复淘汰当前可见块制造持续重建。

## 诊断入口与手机采集

在已运行的游戏网址附加 `perf` 参数，例如 `?region=mine&perf`；已有查询参数时使用 `&perf`。普通游玩不带此参数，不增加诊断 UI 或逐帧采样。

1. 展开右下角“性能诊断”，按需要选择探索、镜头跟随、战斗高负载或区域往返标签。
2. 实际操作该场景，分别进行首进、再次进入、连续走动与镜头跟随、技能密集战斗和多次地图往返；可暂停及恢复记录。
3. 点击“导出 JSON”，保存设备信息、分组帧间隔与主循环回调耗时、超过 50 ms 的长帧数量、资源请求耗时与传输量、加载阶段和当前资源持有估算。最多保留最近 3600 个采样；阶段时间以本次页面导航为基准，跨页往返须保留各页报告。
4. QA 自动验证可使用 `window.__valleyPerformance.reset()` 清除之前的帧样本，再通过 `.report()` 读取结果；仅在开启诊断时提供此入口。

图像与画布采用 RGBA 像素占用估算，不含全部 JS 对象、驱动副本及浏览器开销。支持 `performance.memory` 的浏览器额外记录当前 JS 堆，其值也不包含 GPU 或进程峰值；不支持时记录为不可测。主循环回调耗时不包含完整 GPU 合成成本。

**真实手机验收尚需在目标手机上执行并取得报告。** 本地无头 Edge 和桌面触控模拟不能代替手机 FPS、长时间稳定性或实际峰值内存；本文不将这些项目标为已通过。使用手机诊断前需要目标手机能访问本版游戏，添加参数不会自动部署或公开本项目。
